# IRIS Current State

- **Version:** `v0.2.11` across the workspace and native build. Source tags and published binary releases are separate; production update assets require a signed, explicitly approved release.
- **Product:** A local-first graphical agent environment with movable desktop objects, model providers, permission-gated tools, project workers, schedules, memory, skills and workspace inspection.
- **Storage:** Native repositories use SQLite with revision-checked atomic commits, scoped snapshots and retry on competing writes. Startup imports the current origin's repository data once; localStorage remains as a backup. Invalid JSON aborts the whole import. Browser preview still uses localStorage. Credentials, UI preferences and subtitle checkpoints retain their separate stores. Failed writes report errors; memory is no longer silently evicted at 200 entries.
- **Permissions:** Approved tool execution is claimed atomically before side effects. Requests left in `executing` after interruption cannot be replayed automatically because their external outcome may be unknown. Mandatory shell and GitHub publication approvals remain enforced.
- **Desktop status:** Missing telemetry is displayed as unavailable. Working status follows running coordinators instead of historical tool messages; native Desklet snapshots are shared with the main window.
- **Chat architecture:** Agent, Desklet and GitHub views share a session controller; streaming and pending approvals survive view changes. Agent editing, tool traces and GitHub dialogs are separate components. GitHub errors are visible; locally scaffolded files are not described as pushed.
- **Channels:** Outgoing Telegram and Discord test messages only. Incoming messages, remote approvals and automatic notifications are not connected. Credentials use the OS credential store in the native app; legacy values are removed only after verified durable migration. Browser credentials are session-only. An isolated real OS keyring write/read/delete test passed.
- **Updater:** The local v0.2.10 manifest has an empty signature and points to a plain binary tarball, so it does not establish working automatic installation. Unsigned metadata is rejected before download. Version comes from the desktop package manifest. Native updater permissions are configured; missing summaries, changed target versions and installation failures are shown explicitly. Publisher Markdown is converted to readable text before installation. A real AppImage passed local signed download/install, tamper rejection, failed-extraction rollback and two native boots with retained data using disposable test keys. Production publication remains separate.
- **Shell:** Workspace and Janitor output pipes are drained continuously while retaining at most 64 KiB plus a truncation marker. Workspace execution is permission-gated, not an OS-level jail.
- **Subtitle Studio:** Translation runtime is independent of React window lifetime, with persisted partial checkpoints and manual resume after app restart. Missing translations remain unfinished; original text on export is not counted as translated.
- **Desktop layout:** Windows are brought inside the current viewport, support keyboard movement/resizing through their title bars, and can be saved/restored as named layouts. Styles are split into ordered feature files.
- **Memory evaluation:** Retrieval coverage is distinct from final-answer accuracy. A reproducible CLI report records commit, dirty-tree state, source hashes and measured results in `docs/verification/retrieval-baseline.json`. Benchmark data is loaded on demand.
- **Packaging:** AppImage build handles Arch/CachyOS libraries via `NO_STRIP`. The manually approved draft-release workflow requires a signing key and enables updater artifacts; it has not been triggered.
- **Verification:** Both CI workflows include typecheck, lint, TypeScript tests and Rust tests. Local verification and native boot checks are required before delivery; external messaging and paid model calls are not part of these checks.
